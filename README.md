# Simple Elo

An officer evaluation prototype built on pairwise comparisons and a running Elo rating. One comparison record can be cut by grade band, unit and time. Built with Next.js, FastAPI and DuckDB.

## Features

- **Pairwise comparison**: A, B, tie, or "I can't judge". A can't-judge answer is recorded and moves no rating.
- **Two tracks**: performance and potential are separate questions with separate ratings.
- **Grade bands**: tactical (LT, CPT), operational (MAJ, LTC), strategic (COL and above). Pairs and ratings stay within band. Enlisted ranks sit in a separate unbanded pool.
- **Budgeted rounds**: a set number of comparisons per officer (7 to 15 in the UI, default 10) and a set share of cross-unit pairs (default 20%), in place of all-pairs rounds.
- **Population view**: dashboard filters cut the record by track, band, unit and quarter, including each unit's record against other units.
- **Shuffled replay**: the same comparisons run in many orders, inside each quarter, to show how far order moves a rating.
- **Unrounded ratings**: K = 32, start 1000, rounded for display only.

## Quick Start

### Local, with the synthetic demo force

Needs Python 3.11, [uv](https://docs.astral.sh/uv/) and Node 20 or later. The demo reads the simulation's `E_*.csv` files where they sit; they are not in this repo. Set `ELO_SIM_DIR` or pass `--source` if they are not in the default folder.

```bash
cd backend
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r requirements-dev.txt
.venv/bin/python seed_demo.py --reset
DATABASE_URL=../data/elo_demo.db .venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000
```

```bash
cd frontend
npm install
npm run build
npm run start
```

Open http://localhost:3000. The browser only talks to port 3000; the frontend proxies `/api` to the backend (`BACKEND_URL`, default `http://127.0.0.1:8000`), so keep the backend on loopback.

`npm run dev` works the same on this machine. To open dev mode from another device, list the address in both `ALLOWED_HOSTS` (below) and `ALLOWED_DEV_ORIGINS`:

```bash
ALLOWED_HOSTS=100.113.71.18 ALLOWED_DEV_ORIGINS=100.113.71.18 npm run dev -- -H 0.0.0.0
```

`npm run start` needs only `ALLOWED_HOSTS`. The demo lives in its own database, `data/elo_demo.db`, and every page labels it synthetic. Nothing in it is Army data. The potential track is generated by `seed_demo.py`, because the simulation has no potential answers. Stop the backend before reseeding.

Without `DATABASE_URL` the backend uses `data/elo_ratings.db`, and an existing database is upgraded in place on start.

### Opening it from other devices (Tailscale)

The app answers only to the host names it knows, so a web page cannot point its own domain at this machine (DNS rebinding) and drive the app. Loopback (`localhost`, `127.0.0.1`, `[::1]`) is always allowed. Add each address you open it on, comma separated, in `ALLOWED_HOSTS` when starting the frontend:

```bash
ALLOWED_HOSTS=100.113.71.18,eigens-mac-studio.tail3355e0.ts.net npm run start -- -H 0.0.0.0
```

An entry without a port allows any port; `name:3000` allows only that one. Any other address gets `421 Unknown host`. Pages take no writes (405).

Writes to `/api` are checked as well:
- They must come from a page on one of these hosts (403 otherwise).
- The body must be under 64 KB (413) and arrive within 15 seconds (408; `BODY_READ_TIMEOUT_MS` changes this).
- `POST`, `PUT` and `PATCH` must be `Content-Type: application/json` (415), even with no body, as with `POST /api/rounds/start-first`. A form or no-cors request from another site can only send other types, and the app always sends JSON. `DELETE` is exempt: a browser can't send one cross-site without a CORS preflight, which the backend never grants.

The backend has its own list, `BACKEND_ALLOWED_HOSTS` (default `127.0.0.1,localhost,backend`). Leave it alone unless the frontend reaches the backend under another name.

### Upgrading an existing database (DuckDB 0.9.2 → 1.5.6)

The backend now runs DuckDB 1.5.6. It opens databases written by 0.9.2, but once it has written to one, 0.9.2 can no longer open it. Copy your databases before the first start so you can go back:

```bash
mkdir -p data/backup-duckdb-0.9.2 && cp data/*.db data/backup-duckdb-0.9.2/
```

## API Endpoints

### Personnel
- `GET /api/personnel` - List personnel; filter with `band`, `unit`, `limit`
- `POST /api/personnel` - Add a person with name, rank and unit
- `PUT /api/personnel/{id}` - Update a person. A rank change that crosses a band restarts both ratings; the old record stays under the old band
- `DELETE /api/personnel/{id}` - Soft delete

### Rounds and rating
- `POST /api/rounds/new` - Start a round: `track`, `comparisons_per_officer`, `cross_unit_share`, `quarter`, `band`, `seed`
- `GET /api/comparison/full` - Next pair, with the track's question and ratings
- `POST /api/rate` - Submit `winner_id` (null for a tie) or `cant_judge: true`
- `GET /api/history` - Recent answers

### Population
- `GET /api/meta` - Dataset label, including whether it is synthetic
- `GET /api/filters` - Available bands, units and quarters
- `GET /api/population` - The record cut by `track`, `band`, `unit`, `quarter_from`, `quarter_to`
- `GET /api/replay` - Shuffled replay for a `band`; also `track`, `unit`, `through_quarter`, `shuffles`, `seed`

## Elo Algorithm

- Starting rating: 1000 points
- K-factor: 32
- Results: win 1.0, loss 0.0, tie 0.5. "I can't judge" has no score
- Ratings are stored unrounded

```python
def calculate_elo(rating_a, rating_b, result, k_factor=32):
    expected_a = 1 / (1 + 10 ** ((rating_b - rating_a) / 400))
    expected_b = 1 - expected_a

    new_rating_a = rating_a + k_factor * (result - expected_a)
    new_rating_b = rating_b + k_factor * ((1 - result) - expected_b)

    return new_rating_a, new_rating_b
```

## Usage

1. **Add personnel** with name, rank and unit. The band follows from the rank
2. **Start a round**: pick the track, band, budget and cross-unit share
3. **Answer comparisons**, using "I can't judge" when you have not seen enough
4. **Cut the record** on the dashboard by track, band, unit and quarter
5. **Check order sensitivity** on the Replay page
